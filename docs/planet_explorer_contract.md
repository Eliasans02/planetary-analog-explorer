# Planet-to-surface exploration

The orbital catalog (`planet_catalog` 1.0.0) describes local source-derived visualization textures and optional global radial elevation. It is separate from native local surface data (`surface_catalog` 1.1.0) and calibrated comparison data. Existing 1.0.0 Moon/Earth surface catalogs remain accepted; a Mars surface requires 1.1.0 and retains the HiRISE product coordinate convention in its provenance.

## Actual data and display choices

- The Moon color source is NASA SVS's LRO visualization mosaic. NASA documents color adjustment, inpainting and polar substitution; it is a display texture, never a source for albedo/mineralogy or other scientific measurements. The independently documented LOLA displacement raster supplies physical radial heights where included.
- The Mars orbital source is the [NASA-published Viking display texture](https://science.nasa.gov/3d-resources/mars/), native 1440 × 720 pixels. It is a published display realization, not certified natural RGB, calibrated albedo or a new surface measurement. Preserve the acquired source identity, orientation, dimensions and processing provenance. Earlier ASU tiled Viking derivatives remain historical evidence, not the current Mars quality menu.
- Equirectangular textures are centered at longitude 0, with north at the top and west (-180) at the left. Coordinate-to-UV and sphere mapping must agree at the prime meridian, quarter turns, seam and poles. A source elevation raster's pixel-center registration must be respected when sampling. No fabricated displacement or normals are a substitute for missing DEM data.
- Texture choices are per body: Moon provides 1K, 2K and 4K; Mars provides 1K and default Native 1440 × 720. Native preserves the source dimensions; 1K is a genuine downsample. No 2K/4K Mars upscaling or generative enhancement may imply extra source detail. Display dimensions are not ground measurement resolutions; mesh resolution remains a separate engineering budget. In split view, the quality menu changes only the selected body and retains the other body's choice.

## Globe, marker and astronaut behavior

Both planets support complete azimuth rotation and zoom. Split view presents two independent source-backed globes; synchronization, if offered, concerns camera navigation only, not scientific alignment between planets.

Texture-quality changes replace only the verified image resource. They preserve the camera, native geometry and current verified map while a replacement is loading. The visible status must distinguish displayed detail from requested detail; a failed replacement leaves the old map usable and exposes retry. Superseded asynchronous results must never replace the newest request or leak decoded images/GPU textures.

Within Planet Explorer, each body retains its orbital pose through body switches, split-view changes and landing/return. Relative zoom adapts to viewport fit when the aspect changes. A Locate request is an explicit one-time navigation action; an old request must not override a subsequently saved pose on return from terrain. These poses are navigation state, never measured coordinates or a new reference-frame transformation.

Prepared-site markers are deliberately enlarged interaction targets. Dropping the astronaut on a marker explicitly chooses that named source site. An arbitrary point away from a prepared site must report that detailed local terrain is unavailable and offer a named supported destination. It must not silently snap a user to another place, manufacture terrain, or suggest global first-person coverage. The orbital marker is an approximate locator; native frame differences are retained and no exact global-to-local registration is claimed.

The prepared catalog has six orbital pins: Shackleton rim, Connecting ridge (LOLA Site01), Nobile rim 1 (LOLA Site06), Jezero, Gale crater and Eberswalde crater. Earth’s Hawaiʻi window remains accessible in Surface Archive, giving seven surfaces. A visible count, source/body/name/coordinates/native-grid-spacing cards and separate Locate/Explore actions make overlapping polar markers distinguishable. Pin selection changes the highlighted marker and the selected-site name/Explore action above the globe without moving the camera or rebuilding its scene. Marker positions remain source-derived; selection clears stale Locate requests and unsupported-drop notices. Locate is an explicit camera action; Explore or a supported astronaut drop opens terrain.

Opening a site loads checksum-verified local DEM buffers. The user's first-person entry requires a user gesture; WASD and mouse look operate in the bounded native relief display. Eye height and movement speed are navigation settings, not measured gravity/astronaut dynamics. Movement must remain over valid mesh cells, stop at data boundaries and holes, and release pointer lock and input listeners when leaving. Escape and a clear return-to-orbit action must work. If pointer lock is rejected or unsupported, the viewer must disclose and provide drag-to-look with canvas-focused WASD; it must not silently leave movement unusable. Blur and Escape release focus, keys, capture and the continuous frame loop. A late lock grant after leaving must be released. Normal orbit/pan mode also remains available.

First-person mode provides explicit Start/Resume and Pause actions with visible active/paused state. Rendering the page does not capture keyboard or pointer input. Native X/Z position updates may be throttled while moving, but key release or pause must publish the final position; the display is a navigation readout, not a claim of geodetic accuracy.

## Native-grid analysis

The separate `surface_analysis` 1.0.0 catalog provides prepared descriptive summaries for all seven surfaces. Its `catalog_sha256` binds the exact full surface-catalog response bytes. Records also bind elevation/mask SHA-256, grid dimensions and meter spacing. The consumer enforces bounded local fetching, complete unique records, finite/ranged metrics, coverage counts, fixed histogram bins and consistent fractions and metric bounds. Actual source elevation/mask verification must finish before any analysis is displayed. Missing, stale or inconsistent results are explicitly unavailable; there is no invented fallback.

Results include mean, linear 95th percentile and maximum Horn 3 × 3 slope in degrees, valid-window relief in meters, mean/maximum 3 × 3 range roughness and mean Riley TRI in meters. Slope-distribution bins are [0,5), [5,10), [10,20), [20,30), [30,90] degrees; percentages refer to analyzed centers, with valid-height and interior-center coverage separately reported. Only complete valid 3 × 3 neighborhoods are analyzed; no hole or edge interpolation is performed. Null local metrics remain unavailable.

These are native-grid estimates whose support varies with source spacing and window extent. Projected or center-approximated meter distances are not exact ground distances. Roughness and TRI include the gradient and do not measure rockiness. Provide method/source links and limitations; derive no analog score, safety, temperature, sunlight or suitability result. See [site acquisition and source-pixel verification](research/SURFACE_SITE_EXPANSION.md) and [analysis definitions and limitations](research/SURFACE_ANALYSIS.md).

After base exports, reproduce offline with `data-pipeline/expand_surface_sites.py`, then `data-pipeline/analyze_surfaces.py` and `data-pipeline/analyze_surfaces.py --check` using the project Python environment. Expansion requires verified cached source inputs; analysis generation follows the final catalog.

## Source photographic appearance

The six Moon/Mars windows have nine prepared image layers. Default to **Local image** where a published HiRISE orthoimage exists; otherwise choose **Orbital color**. The three Mars orbital-color drapes now sample the same verified NASA 1440 × 720 display texture as the globe. Local HiRISE imagery and native DEM/analysis identities are unchanged. Global drapes remain coarse and approximately placed; a native window may fit inside one global image pixel. Local images retain published grayscale or enhanced IRB false color, never invented natural RGB. Earth has no prepared photographic layer and explicitly retains relief shading. An asynchronous catalog reload must not replace an explicit user image choice.

Image source and lighting are separate controls. Default **Relief light** uses an sRGB source texture on a white Lambert material, with no elevation vertex colors and no tone mapping. Neutral fill/key intensities are π × 0.38 and π × 0.62, accounting for Three r170's Lambert division by π: the shadow/fill floor is 0.38 and maximum source multiplier is 1. Ground light direction rotates in native grid axes at a fixed 30° elevation; a horizontal surface has a 0.69 linear multiplier. This is visualization lighting, not the real Sun or calibrated photometry. Source illumination and shadows remain baked into the image. **Original image · unlit** uses a white basic material without tone mapping to inspect unchanged source display colors. **Relief shading** separately selects elevation tint. Globe **Color + shape** likewise uses neutral source-texture illumination, while **Original image** retains an unlit source view; Mars remains a sphere without global elevation data.

Image/lighting changes update only materials, textures or light state, retaining native geometry, camera orientation/position, collision and walking state. Source row/pixel-center alignment follows the native DEM grid. Catalog, source-buffer and grid identities, image bytes and decoded dimensions remain verified. A new site must not request its predecessor's imagery or retain stale displayed-source metadata. Superseded/unmounted resources close bitmaps and release GPU textures; failed replacement retains the prior verified display and reports failure.

Expose the actual displayed source label, source/provenance links and limitations. Global placement and source processing remain visible; no generated RGB, calibrated albedo, mineralogy or exact image/DEM registration is inferred. The preceding color checkpoint below validates the earlier unlit-only presentation, not this later lighting/source update.

## Gaussian reconstruction boundary

The original registered splat loading path remains available for future assets. Global textures and DEM meshes are not Gaussian splats. Do not advertise a reconstructed photogrammetric ground scene until real images, reconstruction, metric registration and validation have been supplied. The present work should keep that extension possible without generating plausible-looking rocks or other unobserved geometry.
